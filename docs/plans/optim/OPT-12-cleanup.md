## Проблема 1: Дублирующийся метод `say()` в `TrafficManager`

`TrafficManager` (`traffic.js`) содержит **два** определения метода `say(car, text, duration)`:

```js
// traffic.js:77 — первое определение
say(car, text, duration = 3.0) {
  if (!car.speechSprite) {
    car.speechSprite = makeSpeechSprite(text);
    car.speechSprite.position.y = 2.6;
    car.mesh.add(car.speechSprite);
  } else {
    updateSpeechSprite(car.speechSprite, text);
  }
  car.speechT = duration;
}

// traffic.js:483 — второе определение (перекрывает первое, оно реально используется)
say(car, text, duration = 3.0) {
  if (!car.speechSprite) {
    car.speechSprite = makeSpeechSprite(text);
    car.mesh.add(car.speechSprite);
  } else {
    updateSpeechSprite(car.speechSprite, text);
  }
  car.speechT = duration;
  Events.emit('spatial:shout', { x: car.x, z: car.z, text, type: 'driver', avatar: '🚘' });
}
```

В JS класс с двумя методами одного имени — второе определение **тихо перекрывает** первое,
первое становится полностью мёртвым кодом. Различие между ними: первое ставит
`car.speechSprite.position.y = 2.6` (высота облака речи над машиной), второе — не ставит и
дополнительно эмитит событие `spatial:shout`.

Поскольку реально работает второе определение (нижнее всегда побеждает), `position.y = 2.6`
из первого варианта **никогда не применяется** — высота облака речи трафика зависит только от
дефолта в `makeSpeechSprite()` (`utils.js:218`, `sprite.position.y = 2.4`), что скорее всего и
есть текущее видимое поведение, но выглядит как случайность, а не осознанное решение.

### Решение

Удалить первое определение (`traffic.js:77-87`), оставить второе — оно используется фактически
и несёт дополнительную функциональность (`Events.emit`). Если высота 2.6 (а не 2.4) была
задумана для машин — перенести `car.speechSprite.position.y = 2.6` во второе определение
явно, а не оставлять недостижимым кодом.

## Проблема 3: `peds.js` вычисляет позицию пешехода дважды за кадр

```js
// peds.js:477 (в update()):
const wp = this._worldPos(p, _tempPedWp);
p.x = wp.x; p.z = wp.z;
// ...
this._sync(p);

// peds.js:535 (внутри _sync(), вызванного строкой выше):
_sync(p) {
  const wp = this._worldPos(p, _tempPedWpSync);  // ← тот же расчёт с другим временным объектом
  const h = this.world ? this.world.heightAt(wp.x, wp.z) : 0;
  p.mesh.position.set(wp.x, h + 0.02, wp.z);
  ...
}
```

`_worldPos()` пересчитывается два раза на одного пешехода за кадр — второй раз возвращает то
же самое, что уже посчитано и сохранено в `p.x`/`p.z` строкой выше. Раз координаты уже лежат в
`p.x`/`p.z`, `_sync()` может использовать их напрямую вместо повторного вызова `_worldPos()`:

```js
_sync(p) {
  const h = this.world ? this.world.heightAt(p.x, p.z) : 0;
  p.mesh.position.set(p.x, h + 0.02, p.z);
  ...
}
```

Эффект минимален (30 пешеходов × 1 лишний вызов/кадр), исправление больше про чистоту кода, чем
про измеримый FPS — не тратить на замер отдельное время.
