## Как читать этот план

Каждый `OPT-*.md` — самостоятельная задача с описанием проблемы, решением и чеклистом.
**Все правки — в `src/*.js`. После КАЖДОЙ правки нужно выполнить `python3 build.py`** —
`index.html` — сгенерированный бандл, изменения в `src/` не попадают в запускаемую игру без
пересборки.

Цифры "ожидаемый прирост" в предыдущей версии этого README были оценками без измерения — в коде
не было ничего, что считает FPS/draw calls/GC. **OPT-00 — сделать первым**, он добавляет
измерительный оверлей; после него у остальных пунктов появится возможность подтвердить реальный
эффект, а не гадать.

## Порядок внедрения

```
Этап 0 (обязательно первым): OPT-00 — измерительный оверлей, снять baseline
Этап 1 (наибольший эффект):   OPT-09 → OPT-01 → OPT-02
Этап 2 (заметный эффект):     OPT-10 → OPT-03 → OPT-11
Этап 3 (мелкие правки):       OPT-07 → OPT-06 → OPT-04 → OPT-05 → OPT-12
```

Порядок OPT-09 перед OPT-06 важен: дедупликация материалов зданий (OPT-09) сокращает
`windowMats` с ~230 до ~50 записей, из-за чего dirty-flag для окон (OPT-06) даёт заметно
меньший относительный эффект, если применён раньше.

## Метрики для проверки

Числа ниже — не факт, а гипотеза до замера. **Не переносить их дальше без реального baseline из
OPT-00** — предыдущая версия этой таблицы приводила точные "до" без единого измерения в коде.

| Метрика | Как измерить |
|--------|-----|
| FPS (driving, clear/rain) | Оверлей из OPT-00, усреднённый за 0.5с, одна и та же карта/погода до и после |
| CPU time / frame (JS) | `performance.now()` вокруг `_update()`, оверлей из OPT-00 |
| Draw calls / уникальные материалы | `renderer.info.render.calls`, `renderer.info.memory.*` |
| GC пауз за 5 мин | Вкладка Performance/Memory в Chrome DevTools (не автоматизировать в коде) |
| `world.build()` время | `performance.now()` вокруг вызова, оверлей из OPT-00 |
