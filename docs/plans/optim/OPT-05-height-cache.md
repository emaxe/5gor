# OPT-05 — Кеш высот ландшафта heightAt()

**Приоритет:** 🟢 Лёгкое (эффект переоценён в первой редакции — см. "Честная оценка")
**Сложность:** Минимальная
**Файлы:** `src/citygen.js`
**Ожидаемый прирост:** <0.1 мс/кадр — заметно меньше, чем изначально заявленные «+2-3% FPS»

---

## Описание проблемы

`heightAt(x, z)` вызывается каждый кадр для каждого пешехода и машины игрока:

```js
// peds.js:536 — 1 вызов на пешехода за кадр
const h = this.world ? this.world.heightAt(wp.x, wp.z) : 0;

// citygen.js:heightAt — содержит запрос к оси серпантина через spatial hash (_serpNear)
heightAt(x, z) {
  const hb = this._baseHeight(x, z);
  const q = this._serpNear(x, z);  // ← lookup по ячейке 8×8м + до ~10 проекций точка-отрезок
  // ..смешивание базового рельефа и полки/откоса серпантина..
  return hb;
}
```

*(Примечание: после OPT-12/серпантин-ревизии `_strips` заменён на `_serpNear()` — spatial hash
по оси серпантина, см. ниже актуальный bbox.)*

Для большинства пешеходов (они ходят по плоскому городу) `heightAt()` всегда возвращает 0 — но
вычисления всё равно выполняются.

### Честная оценка масштаба

Пешеходов в игре ровно 30 (`peds.js:138`, `for (let i = 0; i < 30; i++)`), `heightAt()` вызывается
по разу за кадр на каждого (`peds.js:536`, внутри `_sync()`). Итого: 30 × 60 fps = 1800 вызовов/с,
× до 10 итераций по `_strips` ≈ 18 000 операций сравнения в секунду. Это заметно меньше 0.1 мс
на кадр — заявленные в первой редакции «+2-3% FPS» завышены на порядок. Правку стоит делать
(она бесплатна и корректна), но не рассчитывать, что она заметно изменит FPS в замере.

---

## Решение: bbox early-exit

```js
// citygen.js — начало heightAt():
heightAt(x, z) {
  // Машук (0,-448) R=155 + подошва ~7 м + вторая вершина (55,-500) R=70
  // + подходной участок серпантина от проспекта x=128, z=-292
  if (z > -260 || z < -640 || x < -190 || x > 190) return 0; // плоский город — основная зона, где ходят пешеходы

  // ... остальной расчёт без изменений (гора + серпантин)
}
```

(Границы обновлены при переработке серпантина — гора сместилась на `z=-448`, коридор дороги
теперь начинается от проспекта `x=128`; актуальные числа см. `citygen.js:heightAt`.)

Это устраняет вычисления горы и перебор `_strips` для точек в городской зоне за одну проверку —
именно там ходит абсолютное большинство пешеходов.

⚠️ Убран вариант B из первой редакции (LUT 200×200 с ячейкой 4 м). Причины:
- при заявленном масштабе (~18k операций/с) LUT экономит <0.1 мс/кадр — 160 КБ памяти и время
  предрасчёта на `build()` не оправданы;
- lookup по грубой ячейке даёт ступенчатую высоту вместо гладкой интерполяции по оси серпантина
  (полотно шириной 7.2 м, `_serpRoadMesh`) — визуальная регрессия под колёсами игрока при подъёме
  (`player.snapToTerrain`), причём ради выигрыша, который не измерим на глаз.
