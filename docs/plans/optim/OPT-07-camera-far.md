# OPT-07 — Far Plane и туман: уменьшить дистанцию отсечения

**Приоритет:** 🟢 Лёгкое  
**Сложность:** Минимальная  
**Файлы:** `src/game.js`  
**Ожидаемый прирост:** +2-4% FPS (depth buffer + overdraw)

---

## Описание проблемы

```js
// game.js:107
this.camera = new THREE.PerspectiveCamera(62, aspect, 0.1, 3000); // far=3000
this.scene.fog = new THREE.Fog(0x9cc8e8, 500, 1600);              // fog.far=1600
```

Геометрия между 1600м и 3000м от камеры:
- **Невидима** (скрыта туманом)
- **Участвует в depth buffer записи**
- **Попадает в frustum culling** (не отсекается)
- **Снижает точность depth buffer** (depth precision падает с log2(3000/0.1) ≈ 15 бит эффективных)

Горы Бештау находятся на расстоянии ~900-1100м. Телебашня на склоне Машука (~450м по склону). Far plane 1800м сохраняет ВСЮ видимую геометрию при любой погоде.

---

## Решение

### Шаг 1: Уменьшить far plane

```js
// game.js, _initScene():
this.camera = new THREE.PerspectiveCamera(62, aspect, 0.5, 1800); // было: 0.1, 3000
```

`near: 0.5` вместо `0.1` — пешеходы и машины минимум в 0.5м, ближе нет объектов.

### Шаг 2: Согласовать fog.far с new far plane

```js
// game.js, _initScene():
this.scene.fog = new THREE.Fog(0x9cc8e8, 350, 1400); // было: 500, 1600
```

Туман начинается ближе (350м вместо 500м) — горы на ~800-1000м всё равно видны сквозь лёгкий туман.

### Шаг 3: Shadow camera far — НЕ трогать (убрано из плана)

Первая редакция предлагала уменьшить `sun.shadow.camera.far` с 400 до 350 "в согласовании" с
far plane камеры. Это ошибочная связка: shadow camera — отдельная ортографическая камера
(`left/right/top/bottom = ±90`, `game.js:116-117`), её `far` не имеет отношения к far plane
перспективной камеры игрока и far plane этим шагом не трогается. Солнце поднимается по Y до
~102 (`sunY = Math.max(6, 90*dayF + 12)`, `game.js:572`), а здания центра достигают высоты 55 м
(`config.js:134`, `height: [20, 55]`) — сокращение `far` до 350 рискует срезать тени высоких
зданий без какой-либо связи с изменениями far/near из шагов 1-2. Оставить `shadow.camera.far = 400`
как есть, либо менять только по отдельному замеру артефактов теней (см. OPT-02 для полноты
работы с тенями).

### Шаг 4 (опционально): Логарифмический depth buffer

Для устранения z-fighting на дальних объектах:

```js
new THREE.WebGLRenderer({ ..., logarithmicDepthBuffer: true })
```

Осторожно: несовместим с некоторыми MeshPhongMaterial эффектами.

## Чеклист

- [ ] Изменить `PerspectiveCamera` near/far: `0.1, 3000` → `0.5, 1800` (наибольшая польза здесь — рост точности depth buffer от near, а не сокращение far)
- [ ] Изменить `scene.fog`: near 500→350, far 1600→1400
- [ ] НЕ трогать `sun.shadow.camera.far` в рамках этой правки (см. шаг 3 — убрано, отдельный вопрос)
- [ ] Проверить визуально: горы Бештау видны (~900м)
- [ ] Проверить визуально: Телебашня видна (~450м по склону)
- [ ] Проверить визуально: при тумане (fog weather) всё выглядит правильно
- [ ] Проверить визуально: при ночном освещении теней нет артефактов
- [ ] Проверить: клиппинг отсутствует у близких объектов (near=0.5м)
- [ ] Опционально: включить `logarithmicDepthBuffer` и проверить совместимость
- [ ] После правки выполнить `python3 build.py` — иначе изменения не попадут в `index.html`
