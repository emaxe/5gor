# OPT-11 — Троттлинг перерисовки миникарты

**Приоритет:** 🟡 Умеренно
**Сложность:** Минимальная
**Файлы:** `src/ui.js`, `src/game.js`
**Ожидаемый прирост:** убирает ~45 из ~60 canvas-перерисовок миникарты в секунду без заметной потери плавности

---

## Описание проблемы

`ui.renderMinimap(player, orders, world)` (`ui.js:201-263`) вызывается из `_drive()`
(`game.js:712`) **каждый кадр**. Базовая карта города кешируется один раз (`_ensureBaseMap()`,
`ui.js:266`, `if (this._baseMap) return;`) — это уже сделано правильно. Но сам рендер миникарты
не кешируется и делает на каждый вызов:

- `clearRect` на весь canvas;
- повёрнутый `drawImage()` базовой карты 680px (`ui.js:219`) — поворот на `player.heading`,
  масштабирование под `view = 260` единиц мира;
- маршрут до точки высадки (при активном заказе) — `beginPath`/`moveTo`/`lineTo`×3/`stroke`;
- дуги маркеров заказов — `arc()`/`fill()` на каждый открытый заказ в `orders.open`;
- дугу цели и стрелку игрока.

Ни одно из этих значений не требует обновления 60 раз в секунду: позиция игрока и его heading
меняются плавно, но глаз не различает миникарту, обновляемую на 60 Гц, от той же карты на 20 Гц.

---

## Решение: троттлинг вызова, не логики внутри

```js
// game.js, _drive():
this._minimapAccum = (this._minimapAccum || 0) + dt;
if (this._minimapAccum >= 1 / 20) {
  this._minimapAccum = 0;
  this.ui.renderMinimap(this.player, this.orders, this.world);
}
```

Троттлить именно частоту вызова `renderMinimap()`, а не пытаться кешировать промежуточные
canvas-состояния внутри — карта поворачивается вместе с игроком (`ui.js:212`,
`g.rotate(player.heading - Math.PI)`), поэтому кешировать что-то помимо уже кешированной
`_baseMap` смысла не имеет.

⚠️ Не путать с базовой картой полноэкранного режима (`toggleMap()` в `game.js`, состояние `'map'`),
если она использует другой canvas/другой код — эта правка касается только HUD-миникарты,
рисуемой во время вождения.
