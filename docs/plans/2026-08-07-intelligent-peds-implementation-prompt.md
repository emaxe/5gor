**Важные технические детали, которые план уже учитывает (не переизобретай):**
- Маршрут пешехода считается **рёбрами графа**, не суммой `cost` Dijkstra — в `pedgraph.js` есть отдельный комментарий про это.
- `routesFrom(fromId, allowJwalk)` + `pathTo(prev, fromId, toId)` — один проход Dijkstra на активацию пешехода, без повторных полных проходов на каждого кандидата цели. `route()` — тонкая обёртка поверх них для тестов/единичных запросов.
- Узел входа пешехода в граф ищется `nodeOnLane` (строго на его текущей ленте), а не `nearestNode` (геометрически ближайший) — иначе телепорт.
- `_finishEdge` всегда `routeIdx += 1` — поля `advance`/`_edgeAdvance` в текущей редакции плана **нет**, это было исправлено как баг.
- `_classify` не деактивирует пешехода посреди `wait`/`cross`/`turn` (не только `wait`/`cross` — `turn` добавлен отдельно, там своя причина, см. комментарий в плане прямо над кодом `_classify`).
- Животные (`dog`/`cat`) не участвуют в полном ИИ маршрутов — решение подтверждено пользователем в предыдущей сессии, не переоткрывай этот вопрос.
- Разметка переходов (Task 6b) правится только в `citygen.js` (визуал), логика `_startCross`/`_decide` в `peds.js` **не трогается** для этой части — так решили осознанно, чтобы не рисковать регрессией движения без возможности проверить точную геометрию без браузера.
