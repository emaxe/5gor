# 🛠 План рефакторинга и развития проекта 5GOR

## 🎯 Цели рефакторинга
1. **Повышение производительности (WebGL & Memory):** Снижение Draw Calls за счет `InstancedMesh`, выравнивание FPS на мобильных устройствах, снижение нагрузки на Garbage Collector (GC).
2. **Ослабление связности компонентов (Decoupling):** Внедрение Event-Driven архитектуры (EventBus) для изоляции `Game`, `UIManager`, `AudioManager` и `UpgradeSystem`.
3. **Модульность и надежность кода:** Переход на ES-модули, устранение загрязнения глобальной области видимости, добавление JSDoc спецификаций.
4. **Улучшение геймплея:** Погодные эффекты, диалоги пассажиров, расширение гаража.

## 📑 Подробная разбивка по задачам

### 🔹 Задача 1.1: Создание и интеграция EventBus (Event-Driven архитектура)
- **Цель:** Исключить прямые вызовы методов UI и звука из игровой логики (`Game`, `OrdersManager`, `Player`).
- **Файлы:** `src/eventbus.js` (новый модуль), `src/game.js`, `src/ui.js`, `src/audio.js`, `src/orders.js`, `build.py`.
- **Действия:**
  1. Реализовать простой класс `EventBus` с методами `on(event, fn)`, `off(event, fn)`, `emit(event, data)`.
  2. Добавить `eventbus.js` в список модулей в `build.py` (после `utils.js`).
  3. Перевести ключевые события на шину:
     - `order:accepted`, `order:completed`, `order:failed`
     - `money:changed`, `rating:changed`
     - `game:state_changed`, `weather:changed`
  4. Настроить подписки в `UIManager` и `AudioManager`.
- **Критерии приемки:**
  - `orders.js` не вызывает методы `this.game.ui` или `this.game.audio` напрямую.
  - Игра успешно собирается через `python3 build.py` и все звуки/UI откликаются на события.

### 🔹 Задача 1.2: Оптимизация выделения памяти (Vector Pooling в игровом цикле)
- **Цель:** Избавиться от создания `new THREE.Vector3()`, `new THREE.Matrix4()`, `new THREE.Euler()` внутри `update(dt)` циклов.
- **Файлы:** `src/player.js`, `src/traffic.js`, `src/peds.js`, `src/camera.js`.
- **Действия:**
  1. Вынести все временные векторы и матрицы во внешние модуль-скоуп переменные или статичные поля класса (`_tempVec3A`, `_tempVec3B`, `_tempMat4`).
  2. Заменить вызовы `new THREE.Vector3(x, y, z)` внутри регулярных апдейтов на `.set(x, y, z)` или `.copy()`.
- **Критерии приемки:**
  - Отсутствие создания новых объектов Three.js в горячих циклах кадров.
  - Проверка корректности физики движения машины, трафика и пешеходов.

### 🔹 Задача 2.1: Оптимизация 3D-окружения через `InstancedMesh` в `citygen.js`
- **Цель:** Сократить количество Draw Calls за счет объединения одинаковых объектов (деревья, фонарные столбы, светофоры, знаки).
- **Файлы:** `src/citygen.js`.
- **Действия:**
  1. Найти места генерации повторяющихся мешей (деревья, столбы, светофоры).
  2. Заменить групповое создание `THREE.Mesh` на единые `THREE.InstancedMesh` для каждого типа объекта.
  3. Заполнить матрицы трансформации объектов через `.setMatrixAt(index, matrix)`.
- **Критерии приемки:**
  - Существенное уменьшение числа Draw Calls при сохранении визуального вида города.
  - Проверка сборки и работоспособности игры.
