# Дизайн: Интеллектуальные пешеходы

Дата: 2026-08-07
Статус: одобрен (brainstorming)

## Проблема

Текущие пешеходы (`src/peds.js`) ходят по тротуарам случайным образом: цель —
случайный перекрёсток на 1.5–3.5 квартала вперёд, на перекрёстке случайный
выбор «прямо/повернуть/перейти», сквозь фонари/лавки/деревья проходят насквозь,
друг друга не видят. Требуется: каждый пешеход осмысленно идёт «откуда-то и
куда-то», соблюдает ПДД (реалистично, с нарушениями) и обходит препятствия
(статику, других пешеходов, машины).

## Упрощение (по решению заказчика)

Все «жёсткие» правила — маршрутизация, строгое ПДД, обход препятствий — применяются
**только к пешеходам в зоне видимости игрока**. Остальные живут по текущей простой
(и дешёвой) логике. Это сокращает накладные расходы: при 34 пешеходах в радиусе
110 м у игрока в среднем лишь ~5 активных, и Dijkstra/avoidance считаются только
для них.

Зоны (дистанция от игрока, классификация раз в 0.5 с с гистерезисом):

| Зона        | Радиус      | Поведение |
|-------------|-------------|-----------|
| **Активная**| ≤ 110 м     | Полный ИИ: граф-маршрут (Dijkstra), ПДД, обход статики/пешеходов/машин, «прибытие → idle → новая цель» |
| **Ближняя** | 110–150 м   | Текущее простое движение по лентам + боковое смещение вокруг статики + валидация позиции (не внутри пропсов/зданий/машин) — чтобы при повороте камеры пешеход не оказался внутри лавки/машины |
| **Дальняя** | > 150 м     | Текущее поведение как есть |

## Граф ходьбы (`src/pedgraph.js`, новый файл)

Статический граф, строится один раз при инициализации из `world.intersections`
(сетка 9×9, шаг `CFG.CELL=64`, от −256 до 256) и констант. Смещение тротуара —
`PED_SIDE = CFG.HALF + CFG.SIDE/2 = 8`.

### Узлы

По 5 на перекрёсток (`ix`,`iz`):
- 4 «тротуарных» узла — концы тротуарных лент у перекрёстка:
  - `(ix−8, iz)` и `(ix+8, iz)` — подходы вдоль вертикальной дороги;
  - `(ix, iz−8)` и `(ix, iz+8)` — подходы вдоль горизонтальной дороги.
- 1 центральный узел перехода `C = (ix, iz)`.

Плюс по 1 «серединному» узлу на каждую тротуарную ленту (ровно посередине между
перекрёстками, смещение 32 м) — для рёбер незаконного перехода (см. ниже).

### Рёбра

- **Тротуарная лента** (kind `walk`, суммарный cost 1): одноимённые тротуарные узлы
  соседних перекрёстков вдоль дороги (для вертикальной дороги `x=c`:
  `(c−8, zA)↔(c−8, zB)` и `(c+8, zA)↔(c+8, zB)`). Разбивается серединным узлом на
  2 сегмента по cost 0.5: `(c±8,zA) ↔ midpoint ↔ (c±8,zB)`.
- **Зебра** (cost 2, kind `cross`): `(ix±8,iz) ↔ C` и `C ↔ (ix,iz±8)` — переход через
  вертикальную и горизонтальную дороги соответственно.
- **Поворот** (cost 1.5, kind `turn`): тротуарный узел V ↔ тротуарный узел H того же
  перекрёстка (4 комбинации) — срез угла, как текущий `_startTurn`.
- **Jwalk** (cost 3, kind `jwalk`): между серединными узлами двух тротуаров одной
  дороги на ~30% кварталов (случайная выборка с фиксированным сидом). Переход
  через дорогу в неположенном месте. Доступен только пешеходам с trait `violator`.

Структура узла: `{ id, x, z, kind, edges: [{ to, cost, kind }] }`.

### Маршрутизация

**Dijkstra** по весам: прямо (1) дешевле поворота (1.5), поворот дешевле зебры (2);
`jwalk` (3) дороже всех. Функция-фильтр рёбер: `jwalk` доступен только при
`p.violator`.

Пересчёт только при назначении новой цели (не каждый кадр).

## Маршрут пешехода (активная зона)

- **Спавн / вход в зону**: ближайший тротуарный узел к текущей позиции
  (`_worldPos` → поиск по (axis, coord, pos, side)).
- **Цель (гибрид)**:
  - ~50% — ближайший POI: достопримечательности `LANDMARKS` + точки подачи такси
    (`world.pickupPoints`) + заправки (`world.fuelStations`), каждая маппится на
    ближайший тротуарный узел.
  - ~50% — случайный тротуарный узел на граф-дистанции 2–6.
  - Флейвор по архетипу: `grandma` → рынок/ближний POI, `tourist` → Цветник/Провал,
    `runner` → дальний случайный.
- **Движение по рёбрам**: текущая модель — лента → `_updateWalk` к следующему узлу,
  `cross` → `_startCross`, `turn` → `_startTurn`, `jwalk` → `_startCross` с пометкой
  нарушения.
- **Прибытие**: узел цели → режим `idle` на 5–15 с (реплики, «осмотр»), затем новая
  цель. Пешеход всегда идёт куда-то конкретному.
- **Выход из зоны**: маршрут сбрасывается, пешеход живёт по простой логике.

## ПДД (активная зона)

- Переход **только по зебре** (кроме `violator` через `jwalk`).
- На перекрёстке со светофором (нечётные i,j — `world.lights`): ждать у узла-зебры,
  пока `light.state === 2` (зелёный для пешеходов). Без светофора (чётные): ждать,
  пока нет машин в безопасной дистанции (`_carOnRoad`). Существующие
  `_getLightForPed` / `_carOnRoad` переиспользуются.
- **Нарушители** (`violator`, ~20%): могут переходить на красный при зазоре без машин
  и использовать `jwalk`-рёбра.
- Уже идущий по зебре при приближении машины ускоряется (текущий множитель ×1.6);
  свет смены фазы во время перехода — как сейчас (ускорение, не остановка).

## Обход препятствий

1. **Статика** (активная + ближняя зоны). При ходьбе по ленте — боковое смещение
   `laneOff ∈ [−1.6, +1.6]` от центра тротуара. Вперёд-чек (~2.5 м) через
   `world._checkPropCollision` (spatial hash), `world.buildings`, `world.circleColliders`:
   если препятствие — сместить `laneOff` наружу до освобождения; заблокировано
   с обеих сторон — короткая пауза (`waitT`). Когда чисто — `laneOff` плавно к 0.
2. **Пешеходы** (активная зона). Кар-фолловинг: впереди на той же ленте пешеход
   в ≤2.2 м и медленнее/стоит — тормозим; обгон — боковое смещение `laneOff`
   ±1.3 и чуть выше скорость, после обгона вернуть. Попарно только по активным
   (обычно ~5–8).
3. **Машины** (активная + уже в текущей логике перехода). Не входить на зебру при
   машине в опасной дистанции; при близком проезде — текущие `_dodge`/`_knockDown`.

## Интеграция

- Новый файл `src/pedgraph.js`: построение графа, Dijkstra, поиск узла по позиции,
  POI-маппинг, выбор цели.
- `PedestrianManager` (`src/peds.js`):
  - поля: `graph`, `_classifyTimer`, `_activeZoneR`, `_nearZoneR`;
  - методы: `_classify()` (раз в 0.5 с, гистерезис), `_activate(p)`,
    `_deactivate(p)`, `_pickDestination(p)`;
  - поля пешехода: `active`, `route[]`, `routeIdx`, `dest`, `violator`, `laneOff`,
    режим `idle`.
- `_randPlace`: + валидация коллизий против пропсов/зданий/круглых коллайдеров и
  машин (трафик + игрок) с поправкой внутри тротуара; спавн рядом с зоной — на
  ближайшем свободном тротуарном узле.
- Сбитие/убегание — как сейчас (`knockT`/`flee` перекрывают маршрут); после
  `_snapToSidewalk` для активной зоны маршрут пересчитывается.
- `adoptPedestrian` (orders) получает ту же логику автоматически (активен/пассивен
  по зоне).
- Активный пешеход в `wait`/`cross` не деактивируется посреди перехода
  (проверка в `_classify`/`_deactivate`).

## Настройки (config.js)

- `pedActiveRadius: 110`
- `pedNearRadius: 150`
- `pedViolatorChance: 0.2`
- `pedIdleTime: [5, 15]`

## Производительность

- Граф строится один раз (~500 узлов, <1 мс).
- Dijkstra и separation — только активные пешеходы (~5 штук).
- Статик-нюдж — активные + ближние, через spatial hash.
- Классификация зон — раз в 0.5 с с гистерезисом (вход 110, выход 115) против
  фликера на границе.

## Крайние случаи

- Пешеход дальше 210 м от игрока — реплейс (`_randPlace`), как сейчас, но с
  коллизией при близости к зоне.
- `knockT`/`flee`/`kick` перекрывают маршрут; после восстановления — ре-активация.
- Пересчёт маршрута не чаще раза в ~2 с для одного пешехода (защита от «дрожания»
  при смене цели/обгоне).

## Проверка

Сборка `python3 build.py`; запуск `run.sh` (или статика). Ручная проверка в браузере:

1. Активные пешеходы идут по осмысленным маршрутам (POI/случайные), на перекрёстке
   ждут зелёный или пропускают машины, обходят лавки/столбы/деревья/машины/других
   пешеходов.
2. Дальние пешеходы ведут себя как раньше.
3. При повороте камеры никто не стоит внутри объекта/машины.
4. Нарушители (~20%) иногда переходят в неположенном месте или на красный при
   зазоре.
